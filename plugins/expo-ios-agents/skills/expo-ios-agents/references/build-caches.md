# Build caches that work across copies

Every agent works in its own copy of the repo (a worktree or a scratch clone), so every agent starts with an empty DerivedData. Sharing DerivedData itself between copies is wrong: two builds writing to one DerivedData is what produces `build.db: disk I/O error`. Share *compiled output* instead:

- **ccache** covers C, C++ and Objective-C: React Native's own sources when they are built from source, codegen output, reanimated, worklets and other source pods.
- **Xcode's compilation cache** (Xcode 26 and later) covers Swift and Clang.

With React Native 0.80+ and SDK 54+, React core and Expo's modules mostly arrive precompiled, so what's left to compile is your app, codegen, source pods and Swift. A fresh copy with warm caches builds in about a third of the time of a cold one. Measure it on your app before you trust it.

## ccache

```sh
brew install ccache
```

React Native wraps the compiler in `react-native/scripts/xcode/ccache-clang.sh` when ccache is turned on at `pod install`. You can turn it on in any of these ways:

- `USE_CCACHE=1 pod install` (Expo's Podfile template reads it first);
- `"apple.ccacheEnabled": "true"` in `ios/Podfile.properties.json`;
- if `ios/` is generated by `expo prebuild`, `expo-build-properties` with `ios.ccacheEnabled: true` (if your version has it), or a small config plugin that writes the property.

The wrapper uses React Native's own `ccache.conf` unless `CCACHE_CONFIGPATH` is set. That file has no `base_dir`, so a copy at another path never hits what the first copy compiled. Write your own config that repeats React Native's settings and adds the two that matter across copies:

```ini
# ~/.config/ccache/react-native.conf
# a parent of every copy (the main checkout, worktrees, agents' scratch copies)
base_dir = /Users/you
# don't hash the working directory
hash_dir = false
max_size = 20G
# React Native's own settings, kept:
sloppiness = clang_index_store,file_stat_matches,include_file_ctime,include_file_mtime,ivfsoverlay,pch_defines,modules,system_headers,time_macros
file_clone = true
depend_mode = true
inode_cache = true
```

Make every build see it. Put `IOS_Q_CCACHE_CONFIGPATH=~/.config/ccache/react-native.conf` in `~/.config/ios-q/config` and `ios-q run build` exports it, or export `CCACHE_CONFIGPATH` yourself. `base_dir` rewrites only paths below it. If agents' copies live under `/private/tmp` while the main checkout is under `/Users`, either keep the copies under one parent or accept that the two groups won't share. (`/tmp` is a symlink to `/private/tmp`; compilers see the real path.)

**Measure:**

```sh
ccache -z                    # zero the counters
ios-q run build --who me --why "ccache check" -- npx expo run:ios --no-bundler
ccache -s                    # "Hits" against "Misses"; -sv for detail
```

If there are no calls at all, the wrapper isn't installed: check `CC` in a pod target's build settings (`xcodebuild -showBuildSettings | grep -E '^\s+CC ='`), and run `pod install` again with ccache turned on. If there are calls but no hits from a second copy, it's `base_dir` or `hash_dir`. Debug info keeps the first copy's paths, which doesn't matter for agents' builds.

## Xcode's compilation cache

The build settings, all present in Xcode 27's specs:

| Setting | Value |
|---|---|
| `COMPILATION_CACHE_ENABLE_CACHING` | `YES` |
| `COMPILATION_CACHE_CAS_PATH` | one shared folder, e.g. `$(HOME)/Library/Developer/Xcode/CompilationCache.shared` |
| `SWIFT_ENABLE_PREFIX_MAPPING` | `YES`: Swift paths are mapped, so a copy at another path hits |
| `CLANG_ENABLE_PREFIX_MAPPING` | `YES`: the same for Clang |
| `COMPILATION_CACHE_ENABLE_DIAGNOSTIC_REMARKS` | `YES` while checking: the build log shows each hit and miss |

For a raw `xcodebuild`, pass them on the command line:

```sh
ios-q run build --who me --why "compile cache" -- xcodebuild -workspace ios/App.xcworkspace -scheme App \
  -configuration Debug -destination "id=$IOS_Q_UDID" \
  COMPILATION_CACHE_ENABLE_CACHING=YES COMPILATION_CACHE_CAS_PATH="$HOME/Library/Developer/Xcode/CompilationCache.shared" \
  SWIFT_ENABLE_PREFIX_MAPPING=YES CLANG_ENABLE_PREFIX_MAPPING=YES build
```

`expo run:ios` passes no extra build settings, so for it put them in the project. Set them on the app target with a config plugin (`withXcodeProject`, on every build configuration), and on the pods in the Podfile's `post_install`:

```ruby
post_install do |installer|
  # … the template's react_native_post_install call stays first …
  installer.pods_project.targets.each do |t|
    t.build_configurations.each do |c|
      c.build_settings['COMPILATION_CACHE_ENABLE_CACHING'] = 'YES'
      c.build_settings['COMPILATION_CACHE_CAS_PATH'] = '$(HOME)/Library/Developer/Xcode/CompilationCache.shared'
      c.build_settings['SWIFT_ENABLE_PREFIX_MAPPING'] = 'YES'
      c.build_settings['CLANG_ENABLE_PREFIX_MAPPING'] = 'YES'
    end
  end
end
```

With CNG (`ios/` generated), put the Podfile change in a config plugin (`withPodfile`), or it disappears at the next prebuild. ccache and the compilation cache don't stack on the same file: where ccache's wrapper replaces `CC`, Clang runs outside Xcode's cache. Swift is where the compilation cache earns its keep.

**Measure:** `EXPO_PROFILE=1 npx expo run:ios` adds `-showBuildTimingSummary`; for a raw `xcodebuild`, pass that flag yourself. Compare a fresh copy's build before and after, and watch `du -sh` of the CAS folder grow on the first build and stay flat on the second. A cache that never shows a hit in the remarks is costing disk for nothing.

## The rest of a polite build

- **`COMPILER_INDEX_STORE_ENABLE=NO`.** `expo run:ios` already passes it (SDK 58), and `ios-q run build` adds it to a bare `xcodebuild`. Agents don't need Xcode's index.
- **`-jobs 8` and `taskpolicy -c utility`.** The build leaves room for the user's own work. Don't use `taskpolicy -b`: it pins the build to the efficiency cores, and every build then takes longer.
- **`EXPO_CUSTOM_BUILD_ROOT=<the copy>`.** `expo-modules-jsi` builds its xcframework there, not inside the shared `node_modules/.pnpm/…`, where two copies would collide.
- **Its own DerivedData per copy.** That is Xcode's default (`DerivedData/<Name>-<hash of the workspace path>`). The disk sweep removes the folders of copies that no longer exist.
